Modelo C4 e Arquitetura do Sistema BNPL (Aplazo)

Descrição estruturada da arquitetura utilizando o modelo C4 (Contexto e Contêineres), especificação padrão Structurizr DSL e diagramas Mermaid C4 interativos.

1. Visão Geral da Solução

O sistema tem como finalidade fornecer uma infraestrutura de crédito sob demanda (Buy Now, Pay Later - BNPL) para checkouts de e-commerce parceiros e consumidores finais:

Clientes Consumidores

Cadastram-se no ecossistema, recebem aprovação instantânea de linha de crédito baseada em sua faixa etária e realizam compras financiadas em 5 parcelas quinzenais com cronograma automatizado.

Plataformas E-commerce

Integram-se via REST APIs seguras autenticadas por Bearer JWT para oferecer pagamentos parcelados a seus clientes, recebendo confirmações instantâneas de liquidação do empréstimo.

Engine Financeira

Calcula taxas e comissões dinâmicas (Esquema 1 a 13% vs Esquema 2 a 16%), debita saldos remanescentes de forma atômica e estabelece amortização rigorosa com ajuste de centavos residuais.

2. Nível 1: Diagrama de Contexto de Sistema (C1)

O Diagrama de Contexto estabelece as fronteiras do sistema, destacando os atores humanos e sistemas externos com os quais a solução interage dentro e fora do Ecossistema Aplazo.

    System_Ext(ecommerce, "Plataforma de E-commerce / Checkout", "Loja virtual parceira onde o cliente realiza compras utilizando o BNPL.")

    Enterprise_Boundary(b0, "Ecossistema Aplazo") {

    Rel(customer, bnpl_system, "Realiza cadastro e consulta linha de crédito", "HTTPS / JSON")
    Rel(ecommerce, bnpl_system, "Solicita criação de empréstimo em nome do cliente", "HTTPS / REST / JWT")
Elemento Tipo Descrição do Papel no Contexto
Cliente Consumidor Person Usuário final que solicita o limite de crédito inicial e compra produtos com parcelamento quinzenal.
Plataforma de E-commerce System_Ext Checkout da loja virtual conveniada que autentica via JWT para aprovar compras parceladas instantaneamente.
Sistema BNPL Aplazo System (Core) Núcleo de negócio responsável pelo motor de elegibilidade, concessão de crédito, controle de saldo e emissão de planos de pagamento.

3. Nível 2: Diagrama de Contêineres (C2)

O Diagrama de Contêineres expande o Sistema BNPL para detalhar as aplicações em tempo de execução, bancos de dados, portas de rede e protocolos de comunicação que compõem a solução técnica.

Diagrama C2 — Arquitetura de Contêineres Mermaid C4Container

    Container_Boundary(bnpl_boundary, "Sistema BNPL Aplazo") {
        Container(api_app, "BNPL REST API", "Java 21, Spring Boot 3.4, Spring Security", "Disponibiliza endpoints REST para registro de clientes, validação de crédito, autenticação JWT e gestão de empréstimos.")
        ContainerDb(database, "Banco de Dados Relacional", "PostgreSQL 16", "Armazena clientes, limites concedidos, saldos disponíveis, empréstimos, comissões e cronograma de parcelas.")
    }

    Rel(customer, api_app, "Registra-se e consulta saldo", "JSON/HTTPS", "Porta 8080")
    Rel(ecommerce, api_app, "Cria e consulta empréstimos", "JSON/HTTPS / Bearer JWT", "Porta 8080")
    Rel(api_app, database, "Lê e grava dados transacionais com migrações Flyway", "JDBC / SQL", "Porta 5432")
BNPL REST API (Contêiner Aplicação)
  • Stack: Java 21 LTS, Spring Boot 3.4.3, Spring Data JPA, Spring Security, JJWT 0.12.6.
  • Porta de Escuta: 8080 (HTTP/REST com JSON payload).
  • Segurança: Autenticação Bearer JWT para operações restritas de empréstimo.
  • Resiliência: Tratamento global de erros RFC 7807 (ProblemDetail) e validação declarativa Bean Validation.
Banco de Dados (Contêiner de Dados)
  • Engine: PostgreSQL 16 Alpine com conexões pooling HikariCP.
  • Porta de Escuta: 5432 (Driver JDBC oficial).
  • Evolução de Schema: Flyway Database Migrations versionadas no classpath (V1__initial_schema.sql).
  • Consistência: Isolamento de transações READ COMMITTED com trava atômica de decremento de crédito.

4. Especificação Structurizr DSL (workspace.dsl)

Abaixo está o arquivo completo em formato Structurizr DSL (especificação padrão da indústria para modelagem arquitetural C4 as-code). Ele pode ser copiado diretamente para o Structurizr Lite ou compilado via Structurizr CLI.

workspace.dsl DSL Version 1.x 
workspace "Sistema BNPL Aplazo" "Arquitetura da solução de Buy Now Pay Later (BNPL)" {

    model {
        customer = person "Cliente Consumidor" "Consumidor que utiliza crédito BNPL para aquisição de produtos."
        ecommerce = softwareSystem "Plataforma de E-commerce" "Plataformas parceiras e checkouts de vendas." "External"

        bnpl = softwareSystem "Sistema BNPL Aplazo" "Gerencia concessão de crédito, criação de empréstimos e parcelamentos." {
            api = container "BNPL REST API" "Processa requisições de clientes e empréstimos, executa regras financeiras e emite JWT." "Java 21, Spring Boot 3.4"
            database = container "Banco de Dados" "Armazena registros de clientes, linhas de crédito, empréstimos e parcelas." "PostgreSQL 16" "Database"
        }

        # Relações de Contexto (C1)
        customer -> ecommerce "Compra produtos utilizando parcelamento" "HTTPS"
        customer -> bnpl "Realiza cadastro e consulta limite disponível" "HTTPS / REST"
        ecommerce -> bnpl "Envia solicitações de crédito e criação de empréstimo" "HTTPS / REST / JWT"

        # Relações de Contêineres (C2)
        customer -> api "Consome endpoints /v1/customers" "HTTPS / JSON"
        ecommerce -> api "Consome endpoints /v1/loans com token Bearer" "HTTPS / JSON"
        api -> database "Persiste e consulta clientes, empréstimos e parcelas" "JDBC / Flyway"
    }

    views {
        systemContext bnpl "C1_Contexto" "Diagrama de Contexto de Sistema (C1)" {
            include *
            autoLayout lr
        }

        container bnpl "C2_Containers" "Diagrama de Contêineres (C2)" {
            include *
            autoLayout lr
        }

        styles {
            element "Person" {
                shape Person
                background #08427b
                color #ffffff
            }
            element "Software System" {
                background #1168bd
                color #ffffff
            }
            element "External" {
                background #999999
                color #ffffff
            }
            element "Container" {
                background #438dd5
                color #ffffff
            }
            element "Database" {
                shape Cylinder
                background #2A6099
                color #ffffff
            }
        }
    }
}

5. Rastreabilidade de Contêineres e Componentes

Mapeamento sistemático de responsabilidades, componentes de runtime e decisões de design arquitetural:

Contêiner Responsabilidade Principal Tecnologias Utilizadas Padrão Arquitetural
BNPL REST API Autenticação e autorização via JWT, validação de elegibilidade por idade, determinação de esquemas de juros e comissões, cálculo de parcelas com distribuição de centavos, exposição de endpoints REST. Java 21 LTS Spring Boot 3.4.3 Spring Security JJWT 0.12.6 Spring Data JPA Arquitetura em camadas (Controller → Service → Repository) com serviços de domínio isolados e DTOs desacoplados.
Banco de Dados Persistência transacional atômica, integridade referencial com chaves estrangeiras e deleção em cascata controlada, isolamento ACID no débito de saldo disponível e auditoria de timestamps UTC. PostgreSQL 16 Flyway Migrations HikariCP Modelo Relacional Normalizado (Terceira Forma Normal - 3NF) com índices B-Tree em UUIDs públicos expostos e FKs internas.
