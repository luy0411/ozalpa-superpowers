Desafio Técnico BNPL (Aplazo Take-Home)

Consolidação completa da especificação de requisitos de negócio, arquitetura proposta, regras de concessão de crédito, esquemas de pagamento e contrato OpenAPI.

Índice da Página
1. Objetivo Geral & Conceitos 2. Regras de Avaliação de Crédito 3. Esquemas de Pagamento & Juros 4. Cálculos & Parcelamento Quinzenal 5. Contrato OpenAPI 3.0.1 6. Critérios de Avaliação & Stack

1. Objetivo Geral & Conceitos Fundamentais

O teste técnico consiste no desenvolvimento de uma aplicação backend e sistema REST para compras online que cubra os eventos centrais do processo de concessão e gestão de crédito em um modelo de negócio BNPL (Buy Now, Pay Later).

BNPL é uma modalidade de financiamento no ponto de venda que viabiliza a compra de bens e serviços por meio de parcelamento programado, onde o primeiro pagamento ocorre no momento da compra ou em data futura. Dessa forma, a principal exigência tecnológica da plataforma é prover serviços escaláveis, determinísticos e com alta consistência transacional para criação de clientes e controle rigoroso de saldo e empréstimos.

Clientes (Clients)

Indivíduos registrados na plataforma que recebem uma linha de crédito aprovada com base em análise cadastral e idade.

Linha de Crédito (Credit Line)

Montante financeiro máximo disponibilizado ao cliente para financiamento de compras de produtos e serviços.

Empréstimo (Loan)

Cada compra efetivada é convertida em um empréstimo vinculado, deduzindo o valor principal da linha de crédito remanescente.

Esquema & Amortização

Cada empréstimo possui um esquema associado com taxa de comissão e calendário estrito de parcelas quinzenais.

2. Regras de Avaliação e Limite de Crédito

No momento do cadastro via POST /v1/customers, o sistema efetua o cálculo da idade do solicitante com base na data de nascimento (birthDate / dateOfBirth) em relação à data atual do servidor (LocalDate.now()).

Faixa Etária Linha de Crédito Concedida Status de Aceite Comportamento do Sistema
Menor de 18 anos (< 18) $0,00 Não Elegível Rejeição com HTTP 400 Bad Request, código APZ000002
18 a 25 anos (inclusivo) $3.000,00 Aprovado Cadastro concluído, emissão de JWT no header X-Auth-Token
26 a 30 anos (inclusivo) $5.000,00 Aprovado Cadastro concluído, emissão de JWT no header X-Auth-Token
31 a 65 anos (inclusivo) $8.000,00 Aprovado Cadastro concluído, emissão de JWT no header X-Auth-Token
Maior de 65 anos (> 65) $0,00 Não Elegível Rejeição com HTTP 400 Bad Request, código APZ000002
Regra Crítica de Negócio: Clientes menores de 18 anos ou com idade estritamente superior a 65 anos não são aceitos pela política de risco. O sistema não deve persistir o registro no banco de dados e deve responder imediatamente com payload de erro padronizado contendo mensagem explicativa amigável.

3. Esquemas de Pagamento & Resolução de Juros

O sistema opera com dois esquemas pré-definidos de amortização. A determinação de qual esquema será aplicado à compra segue uma ordem prioritária e determinística:

Scheme 1 — Taxa Reduzida (13%) Prioridade 1
  • Taxa de Comissão: 13,00% (0.13)
  • Número de Parcelas: 5 pagamentos quinzenais
  • Frequência: A cada 14 dias (D+14, D+28, D+42, D+56, D+70)
Condição de Aplicação: O primeiro nome do cliente (firstName) inicia com as letras C, L ou H (avaliação case-insensitive, ex.: Carlos, Lucas, Hector).
Scheme 2 — Taxa Padrão (16%) Prioridade 2 & Fallback
  • Taxa de Comissão: 16,00% (0.16)
  • Número de Parcelas: 5 pagamentos quinzenais
  • Frequência: A cada 14 dias (D+14, D+28, D+42, D+56, D+70)
Condição de Aplicação: O ID sequencial interno do cliente é maior que 25 (id > 25), OU como fallback padrão caso nenhuma outra regra se aplique.
Fluxograma de Resolução dos Esquemas (Mermaid)

4. Cálculos Financeiros e Amortização em 5 Parcelas

A conformidade financeira requer precisão monetária decimal rigorosa, sem perda de centavos por arredondamento de ponto flutuante:

Fórmulas de Amortização
1. Comissão de Juros
commissionAmount = roundHalfEven(amount * interestRate, 2)
2. Montante Total
totalAmount = amount + commissionAmount
3. Parcela Base (1 a 4)
baseInstallment = roundDown(totalAmount / 5, 2)
4. Parcela Final de Conciliação (5)
finalInstallment = totalAmount - (baseInstallment * 4)
Cronograma de Vencimento e Ciclo de Vida

As 5 parcelas são agendadas em incrementos de 14 dias (2 semanas) a partir da data de criação do empréstimo:

# Vencimento Status Inicial Descrição
1 D + 14 dias NEXT Próxima parcela imediatamente exigível
2 D + 28 dias PENDING Aguardando vencimento da anterior
3 D + 42 dias PENDING Parcelamento intermediário
4 D + 56 dias PENDING Parcelamento intermediário
5 D + 70 dias PENDING Última parcela (absorve centavos residuais)
Exemplo Prático de Conciliação de Centavos (Compra de $1.000,00 no Scheme 1 a 13%)
  • Valor da Compra (Principal): $1.000,00
  • Comissão Calculada (13%): $130,00 ($1000,00 × 0,13)
  • Montante Total Financiado: $1.130,00
  • Divisão por 5: $1.130,00 ÷ 5 = $226,00 por parcela.
  • Soma das 5 parcelas: 5 × $226,00 = $1.130,00 (exato, resíduo = 0,00).
Status do Empréstimo Gerado ACTIVE Dedução Imediata no Saldo do Cliente -$1.000,00 do limite disponível

5. Contrato OpenAPI 3.0.1

O desenvolvimento da aplicação e dos controladores seguiu com fidelidade matemática e semântica as especificações do contrato Swagger/OpenAPI fornecido pela Aplazo:

Especificação OpenAPI Original (`take-home.openapi.yml`)

Contém os schemas de CustomerRequest, CustomerResponse, LoanRequest, LoanResponse, ErrorResponse e headers exigidos.

Baixar YAML Swagger UI Local (/swagger-ui)
Amostra do Contrato OpenAPI (take-home.openapi.yml) OpenAPI 3.0.1 
openapi: 3.0.1
info:
  title: Aplazo BNPL API
  version: 0.0.1
  description: Minimal BNPL API for customer and loan creation.
servers:
  - url: /{apiVersion}
    variables:
      apiVersion:
        default: v1
paths:
  /customers:
    post:
      summary: Create a customer
      operationId: createCustomer
      requestBody:
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/CustomerRequest'
      responses:
        '201':
          description: Created
          headers:
            Location:
              schema: { type: string }
            X-Auth-Token:
              schema: { type: string }
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/CustomerResponse'
        '400':
          description: Bad Request (APZ000002)
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/ErrorResponse'
  /loans:
    post:
      summary: Create a loan
      operationId: createLoan
      security:
        - BearerAuth: []
      requestBody:
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/LoanRequest'
      responses:
        '201':
          description: Created
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/LoanResponse'
        '400':
          description: Bad Request (APZ000006)
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/ErrorResponse'
