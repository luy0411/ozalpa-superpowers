1. Diagrama Entidade-Relacionamento

O modelo relacional do Sistema BNPL foi projetado na Terceira Forma Normal (3NF), separando claramente o cadastro de limites do tomador de crédito, o registro imutável do empréstimo e o plano de parcelamento quinzenal derivado.

        bigserial id PK "Internal sequential ID"

        varchar last_name "Paternal surname"
        varchar second_last_name "Maternal surname"
        date date_of_birth "Date of birth (18-65 years old)"
        numeric credit_line_amount "Assigned credit line (3000, 5000, 8000)"
        numeric available_credit_line_amount "Remaining credit available"
        timestamptz created_at "Registration timestamp"
    }

    LOANS {
        bigserial id PK "Internal sequential ID"
        uuid external_id UK "Public UUID exposed in API (loanId)"
        bigint customer_id FK "References customers(id)"
        numeric amount "Principal loan amount"
        numeric commission_amount "Calculated interest commission"
        numeric total_amount "Total financed (amount + commission)"
        varchar scheme_name "SCHEME_1 or SCHEME_2"
        numeric interest_rate "0.13 or 0.16"
        varchar status "ACTIVE, LATE, COMPLETED"
        timestamptz created_at "Creation timestamp"
    }

    INSTALLMENTS {
        bigserial id PK "Internal sequential ID"
        bigint loan_id FK "References loans(id) ON DELETE CASCADE"
        int installment_number "Ordinal installment number (1 to 5)"
        numeric amount "Individual installment payment amount"
        date scheduled_payment_date "Biweekly due date (D+14 to D+70)"
        varchar status "NEXT, PENDING, ERROR"
        timestamptz created_at "Creation timestamp"
    }
Estratégia de Identificadores Duplos (Dual-Key)

Cada entidade possui um id surrogate sequencial (BIGSERIAL) para chaves primárias e relacionamentos internos de alto desempenho no banco, e um external_id (UUID) público para exibição e consumo seguro nas rotas da API REST, prevenindo enumeração maliciosa de registros.

Auditoria Temporal e Precisão Monetária

Todas as tabelas contêm o campo created_at com fuso horário (TIMESTAMPTZ) preenchido via CURRENT_TIMESTAMP. Campos monetários utilizam o tipo exato NUMERIC(15, 2) com arredondamento estrito HALF_EVEN para evitar perdas de frações financeiras.

2. Dicionário de Dados

2.1 Tabela: customers Tabela Principal

Armazena perfis de clientes registrados, identificação pessoal, dados biométricos/faixa etária e a alocação de linha de crédito no sistema BNPL.

Coluna Tipo SQL Modificadores / Constraints Default Descrição de Negócio & Regras
id BIGSERIAL PK NOT NULL Auto-increment Chave primária substituta interna. Utilizada na regra de desempate do esquema de crédito (id > 25 qualifica para SCHEME_1).
external_id UUID UK NOT NULL None Identificador único público exposto na API (/v1/customers/{customerId}). Gerado aleatoriamente no momento do cadastro.
first_name VARCHAR(100) NOT NULL None Primeiro nome do cliente. Avaliado na determinação do esquema de pagamento (iniciais 'C', 'L', 'H' qualificam para SCHEME_1).
last_name VARCHAR(100) NOT NULL None Primeiro sobrenome (sobrenome paterno).
second_last_name VARCHAR(100) NOT NULL None Segundo sobrenome (sobrenome materno).
date_of_birth DATE NOT NULL None Data de nascimento do cliente. Utilizada para validação estrita de elegibilidade (idade deve estar entre 18 e 65 anos inclusive).
credit_line_amount NUMERIC(15, 2) NOT NULL None Limite total concedido segundo a idade: $3.000,00 (18 a 25 anos), $5.000,00 (26 a 30 anos), $8.000,00 (31 a 65 anos).
available_credit_line_amount NUMERIC(15, 2) NOT NULL None Limite de crédito remanescente para novas compras. Inicializado igual ao credit_line_amount e debitado atomicamente na criação de empréstimos.
created_at TIMESTAMPTZ NOT NULL CURRENT_TIMESTAMP Carimbo de data e hora do registro do cliente no fuso UTC.
Índices & Constraints (customers):
  • PRIMARY KEY (id)
  • CONSTRAINT uk_customers_external_id UNIQUE (external_id)
  • CREATE INDEX idx_customers_external_id ON customers(external_id);
2.2 Tabela: loans Operações de Crédito

Armazena os contratos de empréstimo e compras parceladas emitidas para os clientes cadastrados.

Coluna Tipo SQL Modificadores / Constraints Default Descrição de Negócio & Regras
id BIGSERIAL PK NOT NULL Auto-increment Chave primária interna sequencial da operação.
external_id UUID UK NOT NULL None Identificador público único exposto nos endpoints (/v1/loans/{loanId}).
customer_id BIGINT FK NOT NULL None Chave estrangeira referenciando customers(id). Vincula o empréstimo ao cliente titular.
amount NUMERIC(15, 2) NOT NULL None Valor principal solicitado da compra. Deve ser maior que zero e $\le$ available_credit_line_amount.
commission_amount NUMERIC(15, 2) NOT NULL None Comissão total de juros calculada: amount * interest_rate (arredondada em 2 casas decimais HALF_EVEN).
total_amount NUMERIC(15, 2) NOT NULL None Valor total financiado da dívida: amount + commission_amount.
scheme_name VARCHAR(20) NOT NULL None Nome do esquema de juros aplicado: SCHEME_1 (13%) ou SCHEME_2 (16%).
interest_rate NUMERIC(5, 4) NOT NULL None Taxa decimal de juros aplicada na operação: 0.1300 ou 0.1600.
status VARCHAR(20) NOT NULL None Estado do empréstimo no ciclo de vida: ACTIVE (ativo/inicial), LATE (em atraso) ou COMPLETED (liquidado).
created_at TIMESTAMPTZ NOT NULL CURRENT_TIMESTAMP Carimbo de data e hora em que a operação foi aprovada e criada.
Índices & Constraints (loans):
  • PRIMARY KEY (id)
  • CONSTRAINT uk_loans_external_id UNIQUE (external_id)
  • CONSTRAINT fk_loans_customer_id FOREIGN KEY (customer_id) REFERENCES customers(id)
  • CREATE INDEX idx_loans_external_id ON loans(external_id);
  • CREATE INDEX idx_loans_customer_id ON loans(customer_id);
2.3 Tabela: installments Cronograma de Parcelas

Armazena o desdobramento das 5 parcelas quinzenais geradas para amortização de cada empréstimo aprovado.

Coluna Tipo SQL Modificadores / Constraints Default Descrição de Negócio & Regras
id BIGSERIAL PK NOT NULL Auto-increment Chave primária sequencial da parcela.
loan_id BIGINT FK NOT NULL None Chave estrangeira referenciando loans(id) com cláusula ON DELETE CASCADE para remoção limpa conjunta.
installment_number INT NOT NULL None Número ordinal da parcela no cronograma: 1, 2, 3, 4 ou 5.
amount NUMERIC(15, 2) NOT NULL None Valor individual devido: total_amount / 5 truncado/arredondado, com centavos residuais reconciliados na 5ª parcela.
scheduled_payment_date DATE NOT NULL None Data exata de vencimento quinzenal (D+14 na #1, D+28 na #2, D+42 na #3, D+56 na #4 e D+70 na #5).
status VARCHAR(20) NOT NULL None Status da parcela: NEXT para a 1ª parcela a vencer; PENDING para as parcelas subsequentes (2 a 5); ERROR se falhar.
created_at TIMESTAMPTZ NOT NULL CURRENT_TIMESTAMP Carimbo de data e hora em que a programação da parcela foi gerada.
Índices & Constraints (installments):
  • PRIMARY KEY (id)
  • CONSTRAINT fk_installments_loan_id FOREIGN KEY (loan_id) REFERENCES loans(id) ON DELETE CASCADE
  • CONSTRAINT uk_installments_loan_number UNIQUE (loan_id, installment_number)
  • CREATE INDEX idx_installments_loan_id ON installments(loan_id);

3. Integridade Referencial e Semântica de Relacionamentos

A arquitetura de dados estabelece garantias estritas de integridade relacional entre o cliente, suas operações contratadas e as parcelas geradas:

Relacionamento CUSTOMERS → LOANS (1:N)
1 : N Cardinalidade: ||--o{
  • Um cliente pode ser cadastrado e inicialmente possuir zero empréstimos ou múltiplos empréstimos ao longo do tempo, desde que a soma de novos valores não exceda seu limite disponível (available_credit_line_amount).
  • Todo empréstimo pertence estritamente a um único cliente (campo customer_id NOT NULL).
  • A remoção de um registro de cliente é restringida (RESTRICT) caso existam empréstimos vinculados, garantindo rastreabilidade contábil e auditoria financeira imutável.
Relacionamento LOANS → INSTALLMENTS (1:N)
1 : 5 Cardinalidade: ||--|{
  • Todo empréstimo aprovado gera atomicamente exatamente 5 parcelas quinzenais na mesma transação.
  • Uma parcela não pode existir sem o seu empréstimo pai (campo loan_id NOT NULL).
  • Caso um empréstimo seja excluído (por exemplo, durante rotinas de cleanup de testes automatizados), todas as parcelas associadas são excluídas automaticamente via ON DELETE CASCADE.
  • A constraint única composta uk_installments_loan_number (loan_id, installment_number) garante que nenhuma duplicata ordinal de parcela seja gravada para a mesma operação.
