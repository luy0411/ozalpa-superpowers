Catálogo de Operações REST da API

Hub central de operações financeiras BNPL (Buy Now, Pay Later), cobrindo integração, autenticação baseada em token JWT, contratos de payload e matriz de erros padronizados.

Acesso Rápido: Endpoints Autenticação JWT Catálogo de Erros Ciclo Operacional

Matriz de Endpoints Disponíveis

A API expõe quatro endpoints REST sob o path base /v1. Toda comunicação trafega estritamente com corpos codificados em JSON (application/json) e respostas com timestamps e identificadores públicos UUID v4.

POST Público / Onboarding

/v1/customers

Cadastro de Cliente & Concessão de Linha

Avalia a idade do solicitante (18 a 65 anos), calcula a linha de crédito automática ($3.000, $5.000 ou $8.000) e emite o token JWT no cabeçalho X-Auth-Token para compras imediatas.

201 Created Ver Detalhes
GET Autenticado / JWT

/v1/customers/{customerId}

Consulta Cadastral e Saldo em Tempo Real

Recupera a linha de crédito total e o saldo remanescente disponível para novas operações (availableCreditLineAmount), permitindo checagem prévia no checkout.

200 OK Ver Detalhes
POST Autenticado / Transacional

/v1/loans

Criação de Empréstimo BNPL

Aplica motor de taxas (Scheme 1 com 13% ou Scheme 2 com 16%), debita atômico do saldo remanescente, divide o montante financiado em 5 parcelas quinzenais e reconcilia eventuais centavos residuais na última parcela.

201 Created Ver Detalhes
GET Autenticado / JWT

/v1/loans/{loanId}

Consulta de Empréstimo e Parcelas

Retorna o extrato completo do empréstimo com juros aplicados, valor principal e o cronograma cronológico das 5 parcelas com status dinâmicos (NEXT, PENDING, ERROR).

200 OK Ver Detalhes

Visão Geral de Autenticação JWT

A API utiliza autenticação stateless baseada em JSON Web Token (JWT) assinado com algoritmo HMAC-SHA256. Não há sessões em memória no servidor, possibilitando escalabilidade horizontal sem afinidade de nó.

1. Emissão no Cadastro (Onboarding)

Ao realizar com sucesso a chamada POST /v1/customers, o servidor devolve o token gerado diretamente no cabeçalho de resposta:

HTTP/1.1 201 Created
X-Auth-Token: eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIzZmE4NWY...
Location: /v1/customers/3fa85f64-5717-4562-b3fc-2c963f66afa7

O subject (sub) do token contém o identificador UUID do cliente e sua role padrão (ROLE_CUSTOMER).

2. Consumo das Operações Protegidas

Em todas as requisições subsequentes para endpoints protegidos, o cliente pode enviar o token através de um dos cabeçalhos suportados:

// Padrão RFC 6750 (Recomendado)
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
// Ou cabeçalho proprietário direto
X-Auth-Token: eyJhbGciOiJIUzI1NiJ9...

Caso o token esteja expirado, adulterado ou ausente, a requisição é interceptada pelo JwtAuthenticationFilter, retornando 401 Unauthorized com código APZ000007.

Interoperabilidade de Headers: O filtro de segurança JwtAuthenticationFilter da API checa primeiramente o cabeçalho Authorization prefixado com Bearer . Caso não esteja presente, faz o fallback automático para o cabeçalho X-Auth-Token.

Fluxo Operacional Ponta a Ponta

Diagrama de sequência exibindo o ciclo de vida completo de um cliente desde o auto-cadastro até a contratação e consulta do empréstimo:

Sequência de Operações da API BNPL Mermaid.js 
sequenceDiagram
    autonumber
    actor User as Consumidor / Checkout
    participant API as BNPL REST API
    participant Sec as JwtSecurityFilter
    participant DB as PostgreSQL 16

    Note over User, API: 1. Onboarding e Concessão de Limite
    User->>API: POST /v1/customers (Nome, Data de Nascimento)
    API->>API: Valida Idade (18 a 65 anos) e calcula limite ($3k-$8k)
    API->>DB: INSERT into customers (external_id, credit_line)
    API-->>User: 201 Created (Location: /v1/customers/{id}, Header X-Auth-Token: JWT)

    Note over User, API: 2. Verificação de Poder de Compra
    User->>Sec: GET /v1/customers/{customerId} (Header Authorization: Bearer JWT)
    Sec->>Sec: Valida assinatura e expiração do JWT
    Sec->>API: Requisição autenticada
    API->>DB: SELECT available_credit_line_amount FROM customers
    API-->>User: 200 OK (creditLineAmount, availableCreditLineAmount)

    Note over User, API: 3. Contratação da Compra (Financiamento BNPL)
    User->>Sec: POST /v1/loans (customerId, amount) (Bearer JWT)
    Sec->>API: Requisição autenticada
    API->>API: Resolve Scheme 1 (13%) ou Scheme 2 (16%)
    API->>DB: UPDATE customers SET available_credit_line -= amount
    API->>DB: INSERT loans + 5 installments (D+14 a D+70 com ajuste de centavos)
    API-->>User: 201 Created (loanId, totalAmount, installments[5])

    Note over User, API: 4. Acompanhamento do Cronograma
    User->>Sec: GET /v1/loans/{loanId} (Bearer JWT)
    Sec->>API: Requisição autenticada
    API->>DB: SELECT loan + installments WHERE external_id = loanId
    API-->>User: 200 OK (status: ACTIVE, installments: [NEXT, PENDING...])

Tabela Consolidada de Códigos de Erro

Todas as respostas de erro da API seguem rigorosamente o contrato padronizado definido pelo ErrorResponse, contendo código interno unificado (APZ000001 a APZ000008), identificador do tipo de erro, mensagem descritiva, timestamp Unix e path de origem:

Contrato JSON de Erro (RFC / OpenAPI)

{
  "code": "APZ000002",
  "error": "INVALID_CUSTOMER_REQUEST",
  "message": "Customer age must be between 18 and 65 years old",
  "timestamp": 1739397485,
  "path": "/v1/customers"
}
Código Enum / Identificador Status HTTP Descrição e Cenário de Disparo Operação Afetada
APZ000001 INTERNAL_SERVER_ERROR 500 Internal Server Falha inesperada ou erro não mapeado no servidor durante processamento interno. Global
APZ000002 INVALID_CUSTOMER_REQUEST 400 Bad Request Campos cadastrais obrigatórios ausentes, mal formatados ou cliente com idade inferior a 18 anos ou superior a 65 anos. POST /v1/customers
APZ000003 RATE_LIMIT_ERROR 429 Too Many Requests Excesso de chamadas à API em curto intervalo, excedendo a cota configurada no gateway. Global
APZ000004 INVALID_REQUEST 400 Bad Request Identificador UUID inválido nos parâmetros de path (ex: invalid-uuid) ou corpo JSON sintaticamente ilegível. GET /{id} / Global
APZ000005 CUSTOMER_NOT_FOUND 404 Not Found O identificador de cliente informado não corresponde a nenhum registro existente na base de dados. GET /v1/customers/{id}
POST /v1/loans
APZ000006 INVALID_LOAN_REQUEST 400 Bad Request O valor solicitado para o empréstimo (amount) excede o saldo remanescente disponível ou é menor/igual a zero. POST /v1/loans
APZ000007 UNAUTHORIZED 401 Unauthorized Cabeçalho de autorização ausente, token JWT expirado ou assinatura HMAC inválida. Endpoints Protegidos
APZ000008 LOAN_NOT_FOUND 404 Not Found O identificador UUID do empréstimo informado na busca não foi localizado na base de dados. GET /v1/loans/{loanId}
