Cadastro de Cliente

POST /v1/customers Onboarding instantâneo e atribuição automática de linha de crédito

Avalia a elegibilidade do solicitante com base em sua data de nascimento, concede o limite financeiro imediato e entrega o token JWT assinado para compras.

1. Visão de Produto e Negócio

Objetivo

Permitir a entrada de novos clientes no ecossistema Buy Now, Pay Later (BNPL) da Aplazo, avaliando instantaneamente a elegibilidade e atribuindo uma linha de crédito inicial automática baseada na faixa etária do solicitante.

Proposta de Valor

  • Onboarding sem atrito: Processo instantâneo com decisão automática de crédito em tempo de requisição, sem análise manual demorada.
  • Autonomia para compras: O cliente já recebe seu identificador único (id), limite de crédito aprovado e um token de autenticação JWT (X-Auth-Token) para realizar compras imediatamente.

Regras de Negócio e Políticas de Crédito

Faixa Etária de Aceitação

O cliente deve possuir idade entre 18 e 65 anos completos no momento do cadastro.

Rejeição: 400 APZ000002

Faixas de Linha de Crédito

  • 18 a 25 anos: Limite de $3.000,00
  • 26 a 30 anos: Limite de $5.000,00
  • 31 a 65 anos: Limite de $8.000,00

Disponibilidade e Segurança

No momento da criação, o saldo disponível (availableCreditLineAmount) é igual à linha concedida (creditLineAmount).

Token JWT no X-Auth-Token

2. Diagrama de Sequência Interno

Fluxo detalhado de execução interna entre as camadas Spring Boot, validação Jakarta, motor de cálculo de linha de crédito, persistência PostgreSQL e gerador de token JWT:

Sequência: CustomerController → CreditLineCalculator → JwtTokenProvider Mermaid.js 
sequenceDiagram
    autonumber
    actor Client as Cliente / E-commerce
    participant Controller as CustomerController
    participant Service as CustomerService
    participant Calculator as CreditLineCalculator
    participant Repo as CustomerRepository
    participant DB as PostgreSQL
    participant JWT as JwtTokenProvider

    Client->>Controller: POST /v1/customers (firstName, lastName, dateOfBirth)
    activate Controller

    Controller->>Controller: Valida campos (@Valid Jakarta)
    alt Campos inválidos
        Controller-->>Client: 400 Bad Request (APZ000002 / APZ000004)
    end

    Controller->>Service: createCustomer(CustomerRequest)
    activate Service

    Service->>Calculator: calculateCreditLine(dateOfBirth, today)
    activate Calculator
    alt Idade < 18 ou Idade > 65
        Calculator-->>Service: throw InvalidCustomerRequestException
        Service-->>Controller: Exception propagada
        Controller-->>Client: 400 Bad Request (APZ000002)
    else Idade Válida
        Calculator-->>Service: Retorna Limite ($3000 / $5000 / $8000)
    end
    deactivate Calculator

    Service->>Repo: save(CustomerEntity)
    activate Repo
    Repo->>DB: INSERT INTO customers (external_id, credit_line_amount, ...)
    DB-->>Repo: CustomerEntity persistido (id sequencial gerado)
    Repo-->>Service: CustomerEntity
    deactivate Repo

    Service->>JWT: generateToken(customer.externalId)
    activate JWT
    JWT-->>Service: Token JWT assinado (HMAC-SHA256)
    deactivate JWT

    Service-->>Controller: CustomerRegistrationResult (CustomerResponse, token)
    deactivate Service

    Controller-->>Client: 201 Created (Location: /v1/customers/{id}, X-Auth-Token: JWT, Body: CustomerResponse)
    deactivate Controller

3. Contrato da Requisição e Resposta

Headers da Requisição e Resposta

Cabeçalho Sentido Obrigatoriedade Descrição
Content-Type Requisição Obrigatório Deve ser obrigatoriamente application/json.
Location Resposta Presente no 201 URI do novo recurso criado: /v1/customers/{id}.
X-Auth-Token Resposta Presente no 201 Token JWT assinado contendo o UUID do cliente no subject para chamadas subsequentes.

Exemplo de Requisição (HTTP Payload)

POST /v1/customers HTTP/1.1
Host: api.aplazo.com
Content-Type: application/json
